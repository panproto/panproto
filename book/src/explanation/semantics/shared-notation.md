# Shared notation

This page defines the meta-notation reused across the other denotational-semantics pages. Read this first.

## In plain terms

We use two complementary notations:

- *Inference rules*, of the form $\dfrac{\text{premises}}{\text{conclusion}}$, define a relation (typically a typing relation $\Gamma \vdash e : \tau$) inductively as the smallest relation closed under the rules.
- *Semantic equations*, of the form $\llbracket e \rrbracket\,\rho = v$, define a function $\llbracket \cdot \rrbracket$ by structural recursion on the syntax. The double brackets emphasize that we are speaking of meaning, not surface text.

The pages use inference rules for static relations and equations for mathematical or operational functions. Not every displayed equation is implemented as a theorem prover, and each page states where its model stops matching the concrete code.

A *context* (also called an *environment*) is a finite map from names to data. Typing contexts map variable names to types; evaluation contexts map variable names to values; theory contexts map sort names to their definitions.

## Environments

Three environment kinds appear repeatedly:

- $\Gamma$: a *typing environment* mapping variable names to types. Notation: $\Gamma, x : \tau$ extends $\Gamma$ with a fresh binding $x : \tau$.
- $\rho$: a *value environment* mapping variable names to values. Notation: $\rho, x \mapsto v$ extends $\rho$ with $x \mapsto v$.
- $\Theta$: a *theory context* mapping sort names to their definitions in a GAT. Used in the theory DSL and in the pushout construction.

A judgment of the form $\Gamma \vdash e : \tau$ asserts that under typing context $\Gamma$, the expression $e$ has type $\tau$. The expression-language page does not assign this judgment to `panproto-expr`, whose current classifier is intentionally weaker.

## Inference rules

An inference rule has the form

$$
\frac{\text{premises}}{\text{conclusion}} \quad (\text{rule-name})
$$

Each premise and the conclusion are judgments. The rule asserts that whenever the premises hold, the conclusion follows. A derivation is a tree of rule applications whose leaves are axioms (rules with no premises) and whose root is the judgment being proved.

## Semantic functions

The semantic function for a syntactic category $C$ is written $\llbracket \cdot \rrbracket_C : C \to D$ where $D$ is the semantic domain. The subscript is omitted when context determines the category.

Common semantic functions:

- $\llbracket \tau \rrbracket : \mathsf{Type} \to \mathsf{Set}$: the set of values of type $\tau$, when the page defines a type interpretation.
- $\mathsf{eval}(e,\rho,c) : \mathsf{Val}+\mathsf{ExprError}$: the resource-bounded operational meaning of an expression under environment $\rho$ and configuration $c$.
- $\llbracket l \rrbracket : \mathsf{Lens} \to (S \to V) \times (S \times V \times C \to S) \times (S \to C)$: the meaning of a lens $l$ as a triple of functions.
- $\llbracket T \rrbracket$ may denote the mathematical model generated by a theory presentation; the concrete compiler returns `panproto_gat::Theory` instead.

## Errors and partiality

The symbol $\bot$ denotes undefinedness only on pages that introduce it explicitly. `panproto-expr` instead returns a concrete error sum, including `StepLimitExceeded` and `DepthExceeded`. Keeping errors separate preserves distinctions that a single bottom element would erase.

## Equality

Equality is page-specific. Values ordinarily use their Rust equality; schemas may be compared by identifiers, structural fingerprints, or a stated kind-and-edge invariant; and morphisms agree when their endpoint theories and assignments agree. Each theorem or check names the equality it uses.
