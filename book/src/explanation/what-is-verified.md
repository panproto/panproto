# What panproto verifies

panproto's correctness rests on a small set of properties that are mechanically checked. Some are verified at compile time (a panic during protocol registration, or an error returned when a migration or theory is compiled); some are verified at runtime when the operation is invoked; some are verified in CI, either by property-based tests over generated inputs or by sweeps over a fixed corpus of measured schemas. This page is the catalog.

If a property is in this list, the implementation enforces it. If you can construct a counterexample, that is a bug.

## Source-code emit coverage

The source-code emitter (`emit_pretty`) qualifies **255 of the 261** vendored tree-sitter grammars on the two bases described in [Source-code emission](./emit-pretty.md#the-verification-tier-api). **248** are corpus-gated: every entry in the grammar's upstream `test/corpus/` round-trips under the strict oracle described in the row above. The other **7** (`python`, `stan`, `bugs`, `jags`, `julia`, `scheme`, `javascript`) are backend-verified: covered by dedicated emit regression tests over the construct surface the quivers transpile backends actually emit, with full corpus pass tracked as follow-on work. The remaining six of the 261 are blocked upstream, not by the emitter:

- **`comment`, `todotxt`, `wolfram`** model their content as opaque free-text spans, so the grammar gives the emitter no structure to reconstruct and the captured text is dropped on emit (a corruption the char-multiset detector flags).
- **`less`** is compiled against an older tree-sitter ABI than the 0.26 runtime loads, so its parser yields only error nodes; there is nothing to round-trip until the grammar is re-vendored.
- **`move`** has no `let`-binding production in the vendored grammar, so real source already parses to an error tree on the way in; this is a parse-layer defect, not an emit one.
- **`test`** parses tree-sitter's own corpus format, whose `===` and `---` delimiters collide with the corpus reader, so it cannot be exercised inside the harness.

The six are the irreducible residual under the current grammars and runtime; closing any of them needs an upstream grammar fix, an ABI re-vendor, or a harness change rather than emitter work.

## How the morphism search is checked

The [span search](../how-to/spans.md) is an exact optimizer over a cost function network, so the property under test is that the returned assignment minimizes the objective. An answer that looks plausible is not evidence that it does. Four algorithms can produce that answer, matching the four variants of `SolverPath`: bucket elimination in the `(min, ⊕)` semiring [@dechter1999bucket] on the exact path; hybrid best-first search [@allouchedegivrykatsirelosschiexzytnicki2015anytime] wrapping depth-first branch and bound that maintains soft arc consistency [@larrosaschiex2004solving] at levels up to EDAC\* [@degivryheraszytnickilarrosa2005existential] on the fallback path; the same hybrid search with a counting all-different propagator [@mccreeshprosser2015backjumping] added on the `monic` path; and a partitioning search over the maximum common induced sub-schema on the `iso` path [@mccreeshprossertrimble2017partitioning]. Depth-first branch and bound is checked in its own right even though nothing dispatches to it bare, since it is the layer the hybrid dives with. Each has to be checked separately, because agreement with the objective is a property of an algorithm and not of the model it runs on.

We check that with three instruments, kept deliberately independent of one another.

The first is an oracle. `solve::oracle::brute_force` visits every assignment the network admits, scores each with the network's own evaluator, and returns the minimum together with every assignment attaining it. It shares no code with the solver, on the reasoning that any logic the two have in common is logic neither one checks: a defective domain walk used by both would move both answers the same way and the comparison would pass. Every step is written out longhand instead. The oracle decodes domain bits with its own loop, walks the product space with a hand-written odometer, and consults no transformed cost table, no propagation state and no bound. Its naivety is the specification, and the price of that naivety is a hard ceiling of 100,000 assignments, above which it refuses to run rather than hanging.

Bucket elimination is checked against the oracle over 500 pseudorandom networks drawn from a fixed seed, on four counts. The optimum matches. The decoded assignment evaluates to that optimum *against an untouched copy of the network*, which is the reading that catches a cost-shifting operation that moved a cost and then failed to move it back. It belongs to the true argmin set rather than merely tying with it. And under the documented tie-break, which reads lexicographically along the value vector in decode order with `⊥` ordered last so that a genuine target beats a dropped vertex, it is the canonical member of that set. The other paths are checked on fixed networks rather than on a sweep: branch and bound at each of its consistency levels, the hybrid wrapper against plain depth-first on the same network, the dispatcher on its exact and its fallback route with the two required to return the same assignment, and the `iso` path over a nine-pair grid of small schemas against its own enumeration. Coverage is thinner there, and we would thicken it by giving each path a random sweep of its own rather than a fixture.

The soft consistency machinery gets its own property, separately from any solver that uses it. A cost-shifting operation is supposed to preserve equivalence [@cooperdegivrysanchezschiexzytnickiwerner2010soft], and equivalence is a statement about the whole cost vector rather than about its minimum. A transformation preserving only the optimum would still let a search report a number that the returned assignment does not attain in the original network, which is a wrong answer of the most awkward kind: internally consistent and externally false. The property tests thus compare the cost of every assignment before and after, over generated networks, generated operation scripts, and each consistency level in turn.

The second instrument is the corpus. Seventy-seven ATProto lexicons give 5852 ordered pairs, and the sweep searches every one of them. Both directions are searched, because a span is not symmetric: the apex is induced on the source, so `(a, b)` and `(b, a)` are different networks with different answers. Every pair reports `proven_optimal`, and in a release build every pair answers inside a 50 ms ceiling, against a measured median near 360 microseconds. Two companion snapshots record what the sweep does not. `lexicon_span_shapes.rs` records the shape of the answer on the 861 unordered pairs drawn from the forty-two lexicons whose `main` definition is a record, one row per pair carrying apex size, quality, which algorithm answered, and the induced width it measured; across those 861 rows the width is 1 or 2, 685 at one and 176 at two, and every answer came from exact inference. `lexicon_domain_shapes.rs` records the shape of the network before anything is solved, over all 5852 ordered pairs, and its summary block is where this book's corpus figures come from: 4950 of the 5852 pairs contain a source vertex with no kind-compatible target and 5117 admit no total morphism at all, the largest single domain per pair runs from 1 through a median of 5 to a maximum of 18, 327 of the 735 pairs admitting a total morphism have a hom-set that is the full Cartesian product of the domains, and the induced width is 1 on 5168 pairs and 2 on the other 684. Together those readings license treating bucket elimination as the primary path rather than a fortunate one, and they remain measurements of a corpus rather than theorems: a schema pair of higher width routes to search and inherits its budget.

The third instrument concerns evidence. Alignment strategies propose anchors, and a stringency tier decides how many strategies run and how permissive each is. Evidence reaches the objective through one reward-only unary cost and through nothing else, so it can change which assignment is optimal and cannot make a feasible assignment infeasible. Two claims follow, and both are tested on real lexicons rather than on synthetic pairs. Feasibility is tier-invariant, so a pair the strict tier aligned cannot come back as "no morphism found" at the permissive one, and optimal cost is monotone in the tier.

The second of those claims carries a caveat that changes how to read it. The shipped anchor weight is zero, so under the shipped weights the evidence term vanishes entirely, the four tiers minimize one objective over one feasible set, and they return the same apex digest and the same quality down to the integer cost unit. Monotonicity under those weights is an equality, and one that could not fail. The invariance test asserts it directly, comparing the weight's bit pattern against zero rather than against a tolerance, so that raising the weight fails the test rather than quietly changing what it means. The monotonicity test in turn runs with the anchor term weighted in, where a tier can reach the optimum at all, and refuses to pass unless the optimum strictly improves at two of the three tier steps. Tier-invariance describes the shipped configuration. Monotonicity is the guarantee that takes over the moment anyone weights evidence into the objective.

## What is *not* verified

The following properties are *not* mechanically checked and should not be assumed:

- **Performance characteristics.** The implementation does not guarantee any particular complexity bound on lens composition, colimit construction, or migration application. The span search's per-pair ceiling is an assertion about one corpus at the widths that corpus exhibits, which are 1 and 2 on every one of its 5852 ordered pairs, and not a bound on the algorithm: both the time and the space of exact inference are exponential in the induced width [@dechter1999bucket], and a wider pair routes to branch and bound and inherits its budget.
- **The cost weights.** The five components the objective combines (vertex name similarity, edge name preservation, outgoing-edge-name Jaccard overlap, out-degree agreement, and anchor evidence) carry weights that have never been calibrated against a labeled corpus of schema correspondences. Everything above checks that the search minimizes the objective those weights define; nothing checks that the objective ranks correspondences the way a schema author would. The anchor weight ships at zero.
- **Constraint compatibility between a mapped vertex and its image.** The objective reads four of a schema's twenty-one fields (`vertices`, `edges`, and the `outgoing` and `between` adjacency indices), so seventeen are obligations the apex has to satisfy without being terms in it, and only five of those seventeen (required edges, coproduct arms, recursion points, spans, and hyper-edge signatures) enter the network as hard constraints. The `constraints` field is not among the five, so nothing in the feasible set stops a morphism sending a vertex carrying `maxLength: 10` onto one carrying `maxLength: 3`. A caller who needs that ruled out restricts the domains before searching.
- **1:n field correspondences.** The morphism class the search ranges over is the length-1 fragment: an `edge_map` sends an edge to an edge and never to a path, so one source field corresponding to several target fields is not expressible as a schema morphism at all. Correspondences of that shape are handled at the value level by `panproto_inst::FieldTransform::ComputeField` and classified `Opaque` when no inverse exists, which is a claim about the data and not about the schema map.
- **A proven optimum when a budget binds.** Exact inference proves optimality by construction; branch and bound proves it only when it terminates without hitting a node, memory, or wall-clock limit. When one binds, the answer comes back with `proven_optimal: false` and `quality_bounds` widened to the interval the search did establish. That interval is a certified bracket rather than a proof, and it separates "0.4, and nothing better exists" from "0.4, and the search ran out of budget before it could rule out 0.9". No row of the 861-pair shape snapshot takes that path; the 5852-pair sweep asserts `proven_optimal` on every pair without recording which path answered, and `proven_optimal` is discharged by branch and bound too, so the sweep does not by itself establish that exact inference ran. The 5852-pair domain snapshot records the induced width of every pair and finds nothing above 2, which is a bound on what the dispatcher can be routing on rather than a record of what it routed to.
- **That `find_morphisms` returns the whole hom-set.** It returns morphisms attaining the optimum, bounded by an engine cap of 1024 that applies to every request rather than only to `max_results = 0`. Every element carries the same quality, so the list is a tie rather than a ranking, and its length is not the size of the hom-set.
- **Round-trip stability of value-level transforms across data with information loss.** A migration that drops a field cannot round-trip the dropped data; the lens laws apply only to the surviving structure.
- **Equivalence of two protocols with isomorphic theories but different parsers.** Two protocols whose theories are the same up to isomorphism are still distinct from panproto's perspective.
- **Application-level invariants not expressible in the schema theory.** "Email addresses must contain `@`" is checked only if the schema actually carries a constraint expressing it.
- **Cocone commutativity on the raw `colimit_by_name` union.** The name-based `colimit_by_name` path used by the C FFI (`pp_gat_colimit`) builds no inclusion morphisms and runs no `verify_cocone`; only constructions through `colimit()` / `pushout_by_name` (including protocol registration) are checked.
- **Edge-level universal factorization for schema merge.** The merge-time `verify_pushout` checks edge cocone commutativity, but the on-demand `verify_pushout_universal` constructs and verifies only the vertex mediator. An edge-level factorization check needs alternative-cocone edge maps in that API.
- **Format-preserving round-trips in the default `schema` binary.** Byte-for-byte round-trips require the `tree-sitter` feature, which the shipped `schema` binary does not enable. A format-preserving parse requested from that binary returns canonical output with no layout complement and prints a notice to stderr; enabling the feature in a source build restores preservation. See [Round-trip with format preservation](../how-to/format-preserving.md).
