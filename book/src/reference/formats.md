# Supported formats

A format is supported when a reader takes its documents into a panproto schema or instance and the result has been checked against what the format's standard says. This page lists the formats that meet that bar, the version of each standard they are read against, and the evidence behind each claim; then the formats and variants that are not supported, with the reason; then the protocols the registry still reads with an earlier reader that has not been checked this way.

The bar is the format contract. For each format it asks that:

- the book names the exact standard or implementation version read, and whether the format's syntax and its interpreted data are read as a tree, a table or a graph;
- every value kind the format has maps exactly, and a feature the model cannot carry is refused with a typed error that names it, never dropped or coerced;
- identifiers, keys and references resolve to their targets through the shared [reference resolution](../correctness/resolution.md), and an unresolved reference is reported;
- validation reports are deterministic, ordered and within the [resource limits](resource-limits.md);
- canonical output is defined, and where the format claims a format-preserving round trip, writing an unedited parse reproduces the input bytes;
- conformance fixtures drawn from the standard, or from a reproducible generator, pass, and the reader agrees with an independent reference semantics on a stated finite scope.

Each supported format has a correctness page that states and proves its laws, and a conformance corpus vendored under [`crates/panproto-io/tests/fixtures/conformance`](https://github.com/panproto/panproto/tree/main/crates/panproto-io/tests/fixtures/conformance) with its licence and upstream commit. A corpus case the reader does not pass is a declared limit: it is listed, with the name of the limit, in a file beside the corpus, the corpus test fails when that list and the failing cases differ, and the correctness page states each limit.

Nothing below is written by hand. The test [`the_book_format_tables_are_generated`](https://github.com/panproto/panproto/blob/main/crates/panproto-io/tests/the_book_format_tables_are_generated.rs) reads the format records in [`book/formats.toml`](https://github.com/panproto/panproto/blob/main/book/formats.toml) and derives every cell from the code and the repository: the protocols, readers and declared shapes from the [protocol registry](https://docs.rs/panproto-protocols/latest/panproto_protocols/registry/index.html), the instance codecs from [`default_registry`](https://docs.rs/panproto-io/latest/panproto_io/fn.default_registry.html), each grammar's upstream and vendored revision from the grammar registry, the declared limits from the limits files, and the correctness pages from the correctness inventory, after checking that each page states the version the record pins. It fails when the committed tables differ from what it derives, so a format that lands with a record appears here, and a protocol without one is listed as not under the contract. It also runs each exclusion's test: a name that no protocol or instance codec answers to, a grammar the grammar registry does not have, or a reader that refuses a document of the excluded variant with the typed error named in the table.

In the shape columns, the part before the slash is the shape the format's syntax is read as and the part after it the shape its data has once references are resolved, as the protocol declares them. The instance codecs column lists the shapes the default instance codecs read for the protocol.
