# panproto

[![Hackage](https://img.shields.io/hackage/v/panproto.svg)](https://hackage.haskell.org/package/panproto)
[![License: MIT](https://img.shields.io/badge/license-MIT-blue.svg)](../../LICENSE)
[![Haskell](https://img.shields.io/badge/GHC-9.12-blue.svg)](https://www.haskell.org/ghc/)

Haskell bindings for [panproto], a schematic version-control system that
treats every supported schema language (around 40, including ATProto, OpenAPI,
AsyncAPI, Avro, FlatBuffers, MongoDB, and Kubernetes CRDs) as views over a
single graph format. Two backends meet at the same capability typeclasses:

* `Native`: a pure-Haskell implementation of the subset that does not need
  the Rust core. Useful when you want a Rust-runtime-free dependency, when
  you need to embed panproto into an existing Haskell pipeline, or for
  property-testing the canonical exchange format.
* `Rust`: an FFI-backed implementation that links against `libpanproto_c`
  (the panproto Rust workspace's C ABI, generated by `safer-ffi`). Hot-path
  operations marshal opaque `u32` handles into a thread-local slab with no
  serialization; cold-path operations marshal CBOR via `ciborium` on the
  Rust side and `cborg` on the Haskell side.

Both backends sit behind capability typeclasses returning plain `IO`, so
`mtl` users lift via `liftIO` and `effectful` users will go through a
separate `panproto-effectful` adapter.

[panproto]: https://panproto.dev

## Status

`0.41.0` is a foundation release. The capability surface grows release by
release alongside the underlying `panproto-c` C ABI:

| Class               | 0.41.0 | Tracking          |
|---------------------|--------|-------------------|
| `ProtocolBackend`   | ✓      | both backends     |
| `SchemaBackend`     | ✓      | both backends     |
| `SchemaValidate`    | ✓      | `Rust` only       |
| `MigrationBackend`  | —      | `0.42.0`          |
| `InstanceBackend`   | —      | `0.43.0`          |
| `LensBackend`       | —      | `0.44.0`          |
| `VcsBackend`        | —      | `0.45.0`          |
| structured `Schema` | —      | `0.45.0`          |

panproto is pre-1.0. The `0.x` series carries arbitrary breaking changes
between minor versions; `panproto` tracks the workspace version.

## Installation

`panproto` is **source-only on Hackage**: the FFI backend links
against `libpanproto_c`, a binary that Hackage cannot redistribute and
cannot fetch from inside its sandboxed matrix builder. Two paths:

### Pre-built binaries (recommended)

```sh
# In your project (after `cabal init`, etc.):
mkdir -p .panproto-c && cd .panproto-c
curl -L "https://github.com/panproto/panproto/releases/download/v0.41.0/libpanproto_c-$(uname -m)-$(uname -s | tr '[:upper:]' '[:lower:]').tar.gz" \
    | tar -xz
cd ..

# Then add to your cabal.project:
echo 'extra-lib-dirs: ./.panproto-c/lib' >> cabal.project.local
echo 'extra-include-dirs: ./.panproto-c/include' >> cabal.project.local

cabal install panproto
```

The `bootstrap/fetch-bindist.sh` script in this directory does the same
thing and writes `cabal.project.local` for you when you have a checkout
of the panproto repo.

### Build `libpanproto_c` from source

Requires a Rust toolchain (`rustup` recommended):

```sh
git clone https://github.com/panproto/panproto.git
cd panproto/bindings/haskell
./bootstrap/dev-link.sh   # builds panproto-c, stages libs under .panproto-c/
cabal build
cabal test                # 31 tests
```

### Native-only (no Rust dependency)

If you only need the pure-Haskell subset, disable the FFI backend:

```sh
cabal install panproto -f-rust
```

## Synopsis

```haskell
{-# LANGUAGE TypeApplications #-}

import Control.Exception (bracket)
import Data.Proxy (Proxy (..))
import Panproto

main :: IO ()
main = do
    -- Build a protocol description.
    let proto = defaultProtocol
            { name     = "my.protocol"
            , objKinds = ["Event", "Subject"]
            }

    -- Native backend: no Rust runtime required.
    nativeRep <- fromCanonical (Proxy @Native) proto
    canon     <- toCanonical nativeRep

    -- Rust backend: same operations, with handles freed on
    -- exception via `bracket`. `withRustProtocol` is the
    -- preferred lifecycle helper.
    withRustProtocol proto $ \rustRep -> do
        canon' <- toCanonical rustRep
        print (canon == canon')   -- True: cross-backend agreement.
```

For schemas, the corresponding entries are `fromCanonicalSchema` /
`toCanonicalSchema` / `withRustSchema`, plus `validateSchema` from the
`SchemaValidate` refinement (Rust backend only at `0.41.0`):

```haskell
import qualified Data.ByteString as BS

validateExample :: CanonicalProtocol -> BS.ByteString -> IO [Text]
validateExample proto schemaCbor =
    withRustProtocol proto $ \rustProto ->
    withRustSchema (CanonicalSchema schemaCbor) $ \rustSchema ->
        validateSchema rustSchema rustProto
```

## Modules

| Module                       | Purpose                                                                            |
|------------------------------|------------------------------------------------------------------------------------|
| `Panproto`                   | Top-level re-exports. Most users only need this import.                            |
| `Panproto.Canonical`         | `CanonicalProtocol`, `CanonicalSchema`, `EdgeRule`, CBOR encode/decode.            |
| `Panproto.Class`             | Backend tags `Native` / `Rust`, capability typeclasses, `validateSchema`.          |
| `Panproto.Errors`            | `PpStatus`, `PanprotoError`, `ErrorEnvelope`, decoders.                            |
| `Panproto.Native.Protocol`   | `instance ProtocolBackend Native`. Pure Haskell.                                   |
| `Panproto.Native.Schema`     | `instance SchemaBackend Native`. Identity over CBOR bytes.                         |
| `Panproto.Rust`              | Rust instances, `withRustProtocol`, `withRustSchema`. Built when `+rust` (default). |
| `Panproto.Rust.Handle`       | Lower-level helpers: `checkStatus`, `consumeVecU8`, `takeLastError`.               |
| `Panproto.Rust.FFI`          | Raw `foreign import ccall` declarations. Prefer `Panproto.Rust.Handle`.            |

## Cross-backend agreement

The fundamental contract between backends is the round-trip law:

```
toCanonical =<< fromCanonical (Proxy @b) p ≡ pure p
```

for every backend `b` and every `CanonicalProtocol` (and analogously for
`CanonicalSchema`). The test suite verifies this by hoisting a value
through Rust, reifying it back, and confirming the bytes match the
input on the Haskell side. Because both backends meet at CBOR, agreement
is checked at the encoding level rather than via differential property
tests, which empirically catch encoding noise more than real bugs.

`Spec.RustRoundtrip.crossBackend` and `Spec.SchemaRoundtrip` cover the
laws; `Spec.Errors` covers the FFI status-code envelope and exception
safety; `Spec.CanonicalRoundtrip` covers the CBOR codec on its own.

## Cabal flags

| Flag           | Default | Effect                                                                         |
|----------------|---------|--------------------------------------------------------------------------------|
| `+rust`        | on      | Builds the FFI backend. Disabling drops the dependency on `libpanproto_c`.     |
| `+native-only` | off     | Excludes the FFI backend even when `+rust` is on. Mutually exclusive with `+rust`. |

## Distribution and binary fetch

The bootstrap scripts under `bootstrap/` handle the binary fetch:

* `bootstrap/dev-link.sh` builds `panproto-c` from the workspace and
  stages `.panproto-c/{lib,include}/` for an in-tree development build.
* `bootstrap/fetch-bindist.sh [version]` downloads the prebuilt
  `libpanproto_c` for your platform from the corresponding GitHub
  Release. Defaults to the workspace version. This is the path
  Hackage users take.

The `panproto-glue` C layer (under `cbits/`) presents pointer-based
wrappers around the by-value `panproto-c` entry points, sidestepping a
GHC `CApiFFI` portability gap on macOS arm64. The bootstrap scripts
build it into `libpanproto_glue.a` and add it to `extra-libraries`.

## Effects integration

The library returns plain `IO`. `mtl`-style stacks lift via `liftIO`:

```haskell
import Control.Monad.IO.Class (liftIO)

handler :: ReaderT AppEnv IO CanonicalProtocol
handler = do
    rep <- liftIO $ fromCanonical (Proxy @Native) defaultProtocol
    liftIO $ toCanonical rep
```

A separate `panproto-effectful` adapter package is planned for
users on `effectful`. `polysemy` users can wrap each capability class
in their own effect and interpret it via `embedToFinal`.

## Performance notes

* Hot-path operations on the `Rust` backend pass `u32` slab handles, so
  there is no per-call serialization. The slab is thread-local; handles
  are not shareable across threads. (A future release may introduce a
  shared variant.)
* `fromCanonical` and `toCanonical` always go through CBOR. Keep
  protocols and schemas around as `RustProtocol` / `RustSchema` handles
  if you need to make many calls against the same value.
* Cross-backend agreement tests serialize through CBOR on both sides
  (`cborg` / `ciborium`), which is the slow path; in real use the
  `Rust` backend stays in handle form.
